# Kubernetes reconciliation and resource lifecycle

The Kubernetes backend stages desired state in SQLite. KubernetesOperationQueue.Schedule adds an outbox record with resource type, resource ID, action and JSON payload; the caller commits it with resource state. ReconciliationOperations stores pending/completed state, attempts, error and timestamps. Not every resource type has its own external runtime reconciler: do not infer execution from a queued account/domain record.

## Website and DNS

WebsiteReconciler resolves current domain/account state, stable PHP identities and storage. It groups pending website operations by resource and considers current state rather than blindly replaying the payload. Storage errors are tracked per site. It applies per-domain routes or removes them for deleted domains, then publishes and activates a complete Apache NFS revision before completing website operations. Account PHP runtime manifests are applied before Apache activation. Obsolete account deployments, services and config maps are retired after activation; policies are retained pending safe pod termination checks. Initial reconciliation and ListenerSet changes can target existing domains. Legacy per-site deployments are not automatically retired.

DnsReconciler groups pending dns-zone work and reconciles current desired records by name; it also retries deferred domain-dns staging in independent scopes/transactions. Website and DNS publication are separate work streams. See [DNS](dns.md).

## Domain deletion

KubernetesDomainService validates exact confirmation and ownership, removes domain desired state and owned DNS/ACME metadata and schedules website/DNS/cleanup work. DeletingDomain:<name> is a durable deletion marker, not a quarantine or secondary resource store. Recreating the same name is blocked while cleanup is pending.

WebsiteReconciler.CleanupDeletedDomainsAsync waits for pending dependent website/DNS operations, confirms that the domain no longer exists and requires the deletion marker. If cert-manager is enabled it waits for certificate removal and removes the managed TLS route. It calls NfsDirectoryProvisioner.DeleteAsync and only then clears the marker and completes cleanup. Pending dependencies do not schedule retries: committed DNS completion and Certificate watch changes wake cleanup, which reads the named Certificate rather than listing all Certificates. Actual cleanup failures remain retryable. Do not claim TLS Secrets are unconditionally deleted; that relies on cert-manager owner references. Verify actual ListenerSet convergence and cleanup separately.

NfsDirectoryProvisioner preserves the existing DirectAdmin directory layout and validates ownership/path safety; it is the storage boundary, not a general file manager. PhpIdentityModel allocates stable account numbers from 10000–30000 using its versioned provider extension; existing filesystem UID/GID are detected at runtime and are not persisted as allocation fields. Retained allocation numbers must not be casually reused.

## Observability

KubernetesDomainService derives provisioning labels from website and DNS operation state (including Pending, Retrying, Configuration applied and Unknown). The domain list/detail can refresh on HostingOperationNotifications; this is an invalidation signal only. Configuration applied does not assert Apache loaded the latest configuration, a public DNS answer or HTTPS readiness. Certificate observation is described separately in [certificates](certificates.md).

The Helm chart provides a shared Apache StatefulSet, dedicated direct configuration NFS mount (read-only in Apache, writable in the panel, no PVC), and named-pod exec authorization for the backend. The backend validates candidate snapshots, atomically selects active.conf and requests graceful reload; failed activation attempts restore the previous revision. No Apache sidecar or ConfigMap polling. Live replica convergence and graceful reload acceptance remain to be tested.

Website reconciliation wakes on coalesced committed operation notifications and Kubernetes watches for Apache pods, website HTTPRoutes and account PHP Deployments, Services, ConfigMaps and NetworkPolicies. It has no idle reconciliation timer; pending execution failures retry with exponential backoff from five seconds to five minutes. Watch snapshots compare relevant resource content across relists and ignore status-only changes. Each watch independently resumes from its last processed resourceVersion; startup and expired cursors require a LIST. Bookmarks advance the cursor without invalidating desired state. Apache replica identity includes pod UID, container ID and restart count; a changed replica set invalidates the activation cache. The actual active include is syntax-checked before graceful reload. Proof of serving convergence and live watch recovery testing are still outstanding.

Certificate and website reconciliation share the wake/retry/watch reconnect loop. Certificate changes and committed domain/ACME mutations enqueue domain IDs; account package changes enqueue affected domains, while global settings changes invalidate the complete inventory. Independent Certificate, ListenerSet and HTTPSRoute watches plus changed relist snapshots cover external routing drift; there is no certificate idle timer. Certificate writes are skipped when the owned spec already matches. Live custom-resource watch recovery still requires cluster validation.

Website and DNS use independent bounded invalidation channels; committed mutations signal relevant workers, while UI-only notifications do not wake them. DNS has no idle reconciliation timer. A separate opt-in StalwartDnsSyncScheduler enqueues due manual mail imports at the configured interval; it is disabled in native mail DNS mode. Dependency-blocked operations remain pending until a DNS invalidation; transient failures retry with capped exponential backoff. CertificateWork retains keyed domain invalidations on its own channel without an idle timer. Signals are drained before reconciliation; SQLite remains authoritative for durable operations.

WebsiteReconciler serializes NfsReconciliation, PhpRuntimeReconciliation and ApacheReconciliation stages to preserve the activation and retirement ordering. Successful directory provisioning and detected ownership are cached by domain for the process lifetime; startup validates again, and deletion still validates storage independently. Out-of-band NFS modifications are not automatically detected. PHP manifests and retirement inventory are cached until desired state or watched resources change. Apache revision activation is skipped when the revision is unchanged and no replica invalidation is pending. A shared inventory scan still occurs on website events; independent keyed workers are not yet implemented. Live watch and storage integration testing remains required.

Kubernetes subdomain ownership uses an explicit provider-owned `SubdomainBindings` relation (child HostedDomain, parent HostedDomain, normalized label). The parent determines the hosting account; the caller cannot specify an owner. The scoped capability authenticates and checks the existing account hierarchy before inventory or mutation validation. Nested subdomains are not supported in this stage. Generic domain deletion refuses linked children and parents; remove children using the subdomain workflow first. Create persists the child and relation atomically with website intent, then signals the existing website channel. The worker provisions the separate full-hostname documentroot, shared Apache vhost, HTTPRoute and account PHP runtime. DNS uses a CNAME in the owned parent zone; missing parent zones defer durable domain-dns work until DNS invalidation. Subdomain creation copies the parent's certificate enablement, provider and key type into independent child ACME intent, queues the child ID after commit, and uses the existing CertificateReconciler. Subdomain deletion stages website, certificate, DNS and storage cleanup using existing workers. HTTP 202 indicates accepted desired state, not DNS or serving readiness.

Subdomain deletion requires parent authorization and exact child FQDN confirmation. It stages deletion of the recorded generated CNAME only if unchanged, removes child ACME intent and file-access metadata, cancels deferred child DNS staging, removes the child and binding, and queues existing website and domain-cleanup operations atomically. Cleanup retains the deletion marker until website/DNS dependencies, Certificate removal and NFS deletion complete. TLS Secret removal depends on cert-manager owner references. Parent deletion is blocked until children are removed explicitly. No new worker or timer is introduced.

## SFTP

The existing owner-scoped SQLite account/key API and durable account/owner/package invalidations remain authoritative. The reconciler publishes one fixed account ConfigMap containing passwd, group, shadow (only invalid password placeholders), per-login public keys and a revision. The single OpenSSH StatefulSet mounts the entire ConfigMap; /etc/passwd, /etc/group and /etc/shadow are symlinks to its projected files. Each new SSH authentication reads the current Unix account and keys. No agent, pod-template patch, per-login Kubernetes mount, reload or restart is required for account changes. A scoped pod exec reads the projected revision before reporting activation; retries while a change is pending are bounded, not idle polling.

OpenSSH uses its standard ChrootDirectory /jails/%u and internal-sftp. The entire dedicated jail export is mounted once. Existing DirectAdmin-compatible web data remains unchanged. The storage operator must prepare root-owned jail ancestors and expose the authorized customer-owned data directory at /jails/<login>/data (e.g. a storage-side bind mount; verify NFS export semantics). The panel mounts that jail export read-only and validates jail ownership plus inode equality as a consistency check before activation. Inode equality alone is not proof of export identity; the storage operator must ensure the mapping is correct. Automatic storage-side jail preparation is not implemented. Do not silently chown or move existing homes. No SYS_ADMIN, CHOWN or DAC_OVERRIDE is granted to the network-facing server.

New accounts and key additions do not disconnect existing sessions. Removing credentials or blocking accounts prevents new authentication after projection; existing session revocation is not yet implemented and must be completed before production. An old projection may remain usable temporarily if the API or kubelet is unavailable. The fixed ConfigMap size is bounded. No password/shell/forwarding. Host keys remain in an operator-managed Secret.

Migration: disable sftpgo.enabled; supply sftp.image (Dockerfile.openssh), sftp.existingSecret (ssh_host_ed25519_key) and sftp.jailExport. Do not serve both workloads. Existing SQLite rows and web data remain intact. Existing SFTPGo PVC is not automatically deleted. Verify actual NFS jail export and quota behavior before production.

## HTTP accounting log contract

Each generated Apache vhost emits `HP_ACCESS_V1 <account-id-N> <domain-id-N> <unix-end-seconds> <status> <received-bytes> <sent-bytes> <duration-microseconds>` to stdout. IDs are literal desired-state configuration, never a request header. mod_logio measures the Apache-side HTTP connection, not external TLS or traffic served directly by Envoy. Health/default vhosts use `HP_SYSTEM_V1`, which cannot be charged to customers. The strict parser rejects malformed records and overflowing byte totals. Request targets, cookies and authorization are not logged in the access format; ordinary error logs remain separate. This is the producer and format contract only, not a durable accounting ledger. A future collector must handle rotation, reconnect, deduplication and gaps before quotas are enforced. No polling added. Disk/inode quotas require storage accounting, not HTTP logs.

Apache log ingestion follows named Apache pod log streams discovered through an independent Kubernetes watch. Each retained record, replay receipt and monthly per-owner/domain byte aggregate commits in one SQLite transaction. Reconnect replays the available current container log; receipts distinguish timestamp, digest and same-timestamp occurrence. This is not a lossless transport: rotation, pod replacement, partial streams and clock anomalies can lose or misattribute replay positions. No automatic suspension is enabled. Access/error logs are exposed via authorized domain reads, with cursor pagination. Only explicitly tagged virtualhost errors are exposed; unscoped platform errors stay private. Error messages may contain application-sensitive data. DirectAdmin domain log adapter is not implemented. Retention and batch ingestion remain open.

HTTP accounting ingestion batches up to 256 records, flushing on stream inactivity (250 ms) or EOF. Customer raw logs default to 30 days (`kubernetesHosting.logRetentionDays`); pruning occurs on ingestion at most hourly, not while idle. Receipts and monthly usage are retained separately; raw log pruning never resets accounting. `/hosting/users/{username}/usage/http` exposes owner-scoped UTC monthly measured bytes, requests and current effective bandwidth limit in bytes. Missing limits remain unknown, unlimited is explicit. Account overview includes HTTP-specific usage fields, never synthetic full DA usage. Official user usage remains 501 until all required measurements exist. No automatic suspension, durable producer spool, receipt retention, or full quota enforcement yet.

Durable segment ingestion foundation: `/hosting/internal/apache-accounting/{segmentId}` is disabled by default; when enabled it requires a dedicated ingestion secret (minimum 32 characters), accepts bounded UTF-8 segments of up to 256 timestamped records, and commits the immutable segment receipt, per-record receipts, customer logs and usage in one transaction. Replays with the same UUID and SHA-256 digest are acknowledged without recounting; conflicting content is rejected. This switch disables the stdout accounting collector to avoid double counting. Do not enable until the separate durable producer is installed and verified. There is no Helm wiring or producer spool in this stage.

Opt-in durable producer: `kubernetesHosting.accountingSpool.enabled` selects Apache piped logging, separate non-overlapping NFS storage, a Python-capable Apache image and an HTTPS panel endpoint with a dedicated Secret. The logger seals batches using fsync and atomic rename, submits UUID-addressed segments, retries failed deliveries, and removes only after 204. Startup replays sealed segments; no idle directory polling. In-memory batches (up to 250 ms/256 records), incomplete temporary files, abrupt pipe loss, NFS failures and deployment transitions are not lossless; hard quota enforcement remains disabled. The operator must prepare the export for UID 1001 and supply a trusted TLS endpoint/image. Do not mix stdout and spool modes during a live rollout without an accounting gap review.

Build the optional producer image with `docker build -f Dockerfile.apache-accounting -t hostingpanel-apache-accounting:local .`, then publish/import it on every eligible node and set `accountingSpool.image`. The smoke workflow builds the image and exercises sealed segment persistence, failed submission and acknowledged deletion using isolated fixtures. This is not a real NFS crash test.

The clean-server installer supports explicit second-stage activation of durable HTTP accounting, including a separate ZFS/NFS export, token Secret, optional local image build and generated Helm values. See installer/README.md. Bootstrap stays in stdout mode until an administrator configures a trusted HTTPS origin; the host-side health probe does not establish in-pod connectivity.

The spool now appends each complete record to a locked `.open` journal and fsyncs before accepting the next record. Sealing preserves the UUID and atomically renames the journal to `.ready`. On startup, orphan journals are recovered under nonblocking exclusive locks; complete lines survive and incomplete trailing bytes are reported. Live journals are never recovered by another writer. This reduces the in-memory loss window but does not protect bytes still in Apache's pipe or an interrupted write, and requires verified NFS locking/fsync semantics. Legacy `.tmp` files remain untouched for manual recovery. No idle polling added.

The OpenSSH CI workflow builds the real image and exercises three disposable logins (two sharing a UID), successful transfers, on-disk numeric ownership, wrong-key rejection, shell denial and cross-jail reads. These are local bind mounts, not a live Kubernetes NFS or ZFS quota test.
